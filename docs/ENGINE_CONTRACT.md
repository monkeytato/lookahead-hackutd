# Engine contract (`src/domain/engine/`)

All engine modules are pure TypeScript over `src/domain/types.ts`. The UI imports **only** from
`src/domain/engine/index.ts`. Numbers are produced here, never by the LLM. Randomness is seeded
(mulberry32) so a replay always produces identical output.

Scenario time is in **minutes** (`t`), where `t = 0` is scenario start. Clock values (`p10/p50/p90`)
are **absolute scenario minutes** at which a node is lost, not durations.

| File | Export | Signature / behaviour |
| --- | --- | --- |
| `rng.ts` | `mulberry32(seed)` | `() => number` in [0,1) |
| `cascade.ts` | `runCascade(facility, faults, opts)` | `faults: {assetId, t}[]`; `opts: CascadeOptions = { horizonMin: number; runs?: number (400); seed?: number (7); extraEdges?: DependencyEdge[] }`. Uses only `confirmed` edges plus `extraEdges`. Each run samples every edge delay from its triangular `{min,mode,max}`. Loss time of a node = min over its groups of (max over group members of `lossTime(member) + delay`); an edge with no `redundancyGroup` is its own group; a faulted node is lost at its fault `t`. Propagate with a Dijkstra-like relaxation until stable. Returns `Record<ID, ImpactClock>` for every node lost within the horizon in at least one run (percentiles over runs where lost, `null` if lost in < 10/50/90 % of runs as appropriate; `probWithinHorizon`; modal `path` from the fault to the node; `weakestAssumption` = `basis` of the edge on the path with the widest `max-min`). |
| `thermal.ts` | `inletTempAt(baseC, rackKw, coolingLostAt, t)` | Display-only per-rack curve for the synthesized readings of `simulateScenario`. Before `coolingLostAt` (or when `null`) returns `baseC`. After it: `base + ΔTmax·(1 − e^(−(t−lost)/τ))` with `ΔTmax = min(30, 3·rackKw)` °C and `τ = 2 + 24/rackKw` min. Indicative, not CFD; predictions use `thermalZone.ts`. |
| `thermalZone.ts` | `zonesFor(facility)` → `HallSpec` | Zones = CRAH pairs read from the `cools` edges (fixture: north CRAH-1/3 rows A–B, south CRAH-2/4 rows C–D). CDU-fed racks are direct-liquid-cooled and put 15 % of their power into their row's zone (assumption). |
| | `fansOffMinutes(zone, θ, thresholdC, horizonMin)` | Closed form of the two-node energy balance with constant P: `T_a(t) = T0 + P·t/C + (C_m/C)·D∞·(1 − e^(−t/τ))`, `C = C_a + C_m`, `τ = 1/(G·(1/C_a + 1/C_m))`, `D∞ = P·τ/C_a`; `C_a = ρ·c_p·A·(ceiling + plenum)·(1 + mix)`, `C_m = N·m_rack·650 J/kg·K`, `G = k_G·ε·ρ·c_p·0.059 m³/s per kW·P_kW`. Minutes to the threshold, or `Infinity`. |
| | `fansOnMinutes(hall, θ, waterShare, thresholds, horizonMin)` | Three nodes (air, IT mass, chilled water) with fans running and no chiller (`waterShare` 1) or no flow (coil water only, `waterShare` = coil_frac). Explicit Euler, dt = 2 s; CRAH airflow 1.2 × IT airflow (assumption), coil effectiveness 0.75. |
| | `zoneClocks(hall, θ)` | `{ off: zone → [t32, tTrip], chw: [t32, tTrip], flow: [t32, tTrip] }`, minutes after the loss. Two clocks: the 32 °C envelope and service impact at `θ.tTripC ~ U(40, 45)` °C. |
| | `simulateThermal(params)` | Port of `research/scripts/thermal_backtest.mjs`. Backtest in `tests/engine/thermalZone.test.ts` at k_G = 2: WP179 Ex. 1 peak after the loop-volume fit, 5-min restart within 2.5 °C, CFD room 60 s / 300 s within 1.5 / 3 °C, energy conserved. |
| `water.ts` | `simulateWater(facility, leak, horizonMin, frameEveryMin = 1)` | Height-field diffusion on a 0.5 m grid covering all zone rects. Ground height per cell = zone `elevation` (m). Cells outside zones are walls. Racks/equipment footprints (except `drain`, `pipe`) are plinths +0.05 m. Each substep: every cell passes water to lower neighbours (surface = ground + depth), capped flow per step, mass-conserving; drain cells remove 30 % per min of local depth. Source cell nearest `leak.{x,z}` adds `ratePerMin` litres/min starting at `leak.startT` (1 L over 0.25 m² = 4 mm). Returns `WaterGrid` with frames every `frameEveryMin`. |
| | `depthAt(grid, x, z, t)` | mm, nearest frame ≤ t |
| | `waterArrival(grid, facility, thresholdMm = 1)` | `Record<assetId, number>` first frame `t` at which any cell under the asset footprint (or within 0.5 m) is ≥ threshold. Pipe/drain assets excluded. |
| `readings.ts` | `freshness(reading \| undefined, now)` | `'missing'` if undefined; `'stale'` if `now − reading.t > 2 × expectedIntervalMin`; else `'fresh'`. |
| | `severityFor(metric, value, thresholds)` | Severity from `Threshold` (`dir` aware): ≥ alarm → `critical`, ≥ warn → `warning`, else `normal`. `leak` ≥ 0.5 → `critical`. |
| | `readingKey(r)` / `latestReadings(readings, now, sources?)` | key `assetId|metric|source`; latest reading per key with `t ≤ now`. |
| `verification.ts` | `compareReadings(installed, references, ctx)` | `ctx = { now: number; thresholds: Threshold[] }` → `{ verdict: Verdict; rationale: string; qualityFlags: string[] }`. Rules: metric/asset mismatch or no reference or a stale reference → `inconclusive`; both abnormal (≥ warn) → `corroborated_abnormal`; installed abnormal and reference normal with a material gap (> 3 °C temp, > 30 % vibration) → `measurement_disagreement`; installed normal and reference normal → `not_corroborated_in_session`. Rationale never says "sensor broken" or "equipment safe". |
| `priority.ts` | `rankIncidents(incidents, ctx)` | `PriorityContext = { facility; clocks: Record<ID, ImpactClock>; now: number; tasks: Task[]; employees: Employee[] }`. Factors (0–1 scores) with operator-configured illustrative weights: service impact (criticality of services on racks within the incident's downstream clocks) 0.30, urgency (minutes to earliest p50 downstream loss, ≤ 10 → 1) 0.25, redundancy (does incident remove a redundant path: CRAH pair, UPS pair, PDU pair) 0.15, evidence quality (corroborated 1, unverified 0.6, inconclusive 0.5, disagreement 0.25, not_corroborated 0.3 — disagreement still keeps a floor, never zero) 0.15, resource feasibility (eligible available employee exists) 0.10, consequence of wrong action 0.05. Return sorted desc, each with `policyVersion = POLICY_VERSION`, `factors[].note` human-readable, and `resolvingCheck` when evidence is `unverified`/`inconclusive`/`measurement_disagreement`. |
| `routing.ts` | `findRoute(facility, fromWp, toWp, opts)` | `opts = { skills: Skill[]; closedEdgeIds?: ID[]; walkSpeedMps?: 1.2 }`. Dijkstra over `walkEdges` (undirected), skipping `closed` / `closedEdgeIds` / `restrictedTo` not in skills. Returns `Route` with `etaMin` (+0.5 min per restricted door), `assumptions` (walk speed, check-in source), or `ok:false` with `blockedReason`. Never straight-line fallback. |
| `tasks.ts` | `transition(task, action, ctx)` | `TaskAction = {type:'assign', ownerId} \| {type:'accept'} \| {type:'decline', reason} \| {type:'depart'} \| {type:'arrive'} \| {type:'confirm_asset', scannedId} \| {type:'start'} \| {type:'record_step', stepId, result, note?, evidenceId?} \| {type:'block', reason} \| {type:'unblock'} \| {type:'submit'} \| {type:'approve'} \| {type:'request_changes', reason} \| {type:'reopen', reason} \| {type:'cancel', reason}`. `ctx = { actor: string; t: number; expectedVersion: number }`. Version mismatch → error `stale_version`. Illegal transition → error. `confirm_asset` with wrong id → error `asset_mismatch` (A13). `start` requires `assetConfirmed`. `submit` requires all required steps recorded (`canComplete`). `submit` on a no-review task goes straight to `completed`. Returns `{ok:true, task (version+1), event: OpEvent}` or `{ok:false, error}`. Never mutate input. |
| | `suggestAssignees(task, employees, facility, now)` | `AssigneeSuggestion = { employeeId; eligible: boolean; reasons: string[]; route?: Route; score: number }`. Filter by skills, zone access (asset zone in `zones`), availability; rank by eta (route from last check-in; stale check-in > 30 min adds a "location stale" reason and +5 min penalty), workload. Sorted best first; ineligible included with reasons. |
| `handoff.ts` | `buildHandoff(input)` | `HandoffInput = { now; incidents; tasks; employees; events: OpEvent[]; verifications: VerificationSession[]; clocks; staleAssetIds: ID[]; facility }` → `HandoffNote = { generatedAt: number; source: 'local_rules'; happening: string[]; verified: string[]; uncertain: string[]; done: string[]; owners: {item, owner}[]; doNotRepeat: string[]; watch: {assetId, atMin, why}[] }`. `handoffToMarkdown(note, wallClock: (t)=>string)`. |
| `simulate.ts` | `simulateScenario(input)` | `ScenarioRunInput = { facility; scenario; seedReadings: Reading[]; extraEdges?: DependencyEdge[]; extraFaults?: {assetId,t}[]; fixes?; runs?; seed?; mode?: 'script' \| 'forecast'; forecastAt?: number; hypotheses?: string[] }` → `ScenarioRun = { clocks; water?: WaterGrid; waterArrival: Record<ID, number>; derivedEdges: DependencyEdge[]; readingsAt(t): Reading[]; visualAt(t): Record<ID, AssetVisualState>; stepsUntil(t): ScenarioStep[]; hazardAt; restoredAt; assumedFaults: AssumedFault[] }`. `mode: 'script'` (default) replays every scripted fault: the world (stage, replay). `mode: 'forecast'` runs `forecastScenario(facility, scenario, forecastAt, hypotheses)` first (audit C1): only faults observed or inferable by `forecastAt`, plus opted-in hypotheses; `assumedFaults` lists each with its basis. Wet assets (from `waterArrival`) become faults at arrival `t` and get a derived `shares_space` edge (`basisKind: 'model'`, basis "water-layer arrival, approximation"). `readingsAt(t)` = seed readings + scenario step readings + synthesized readings for racks whose cooling clock has passed (via `inletTempAt`), only `t ≤ now`. `visualAt(t)`: severity = max(threshold severity of latest installed reading, clock severity — lost by `t` → critical, `p50 − t ≤ 10` → critical, `≤ 30` → warning, else advisory if on any clock); freshness from installed readings; `heat` = clamp((inlet − 18)/14); `clockMin = p50 − t` if > 0; `wet` if arrival ≤ t. Memoize per `t`. |
| `cascade.ts` | `compileGraph(facility, extraEdges?, extraIds?)` / `runOnce(g, delay, faultT, fixT, loss, rec, cause)` | The cascade split into a compiled graph and one run over given edge delays, own-fault and fix times (recovery rules as `runCascade`). `runCascade` is a loop over `runOnce` and is bit-identical to before. |
| `observable.ts` | `detectedAt`, `faultObservedAt`, `leakInferableAt`, `observedFaults(scenario, t)`, `scriptedHypotheses(facility, scenario, t)`, `forecastScenario(facility, scenario, t, include?)` | A fault at t_f is observed at the first observation step on its asset at or after t_f (else at t_f: BMS trip alarm, assumption). A leak is inferable only from an observation step at its source after it starts. Every other scripted fault is a `FaultHypothesis { id, assetId, t, label, prior, basis, basisKind }` with prior `1 − exp(−rate · hours left)` from INL/EXT-21-65055 per-hour rates, or 0.02 (range 0.005–0.1, assumption) when a precursor alarm is active. |
| `evidence.ts` | `evidencePosterior({ metric, installed, reference, neighbours?, modelBaseline, priorReal?, errorModel? })` | `P(real) = LR·π / (LR·π + 1 − π)`. Temperature: `LR = t_ν(y; x_installed, √(σ_inst² + σ_ref² + σ_sp²)) / t_ν(y; μ_baseline, √(σ_model² + σ_ref² + σ_sp²))`, ν = 4. Water probe: sensitivity 0.95, specificity 0.98 (assumption). `DEFAULT_ERROR_MODEL` carries each σ with its basis. Supply water, battery, UPS, flow, pressure and vibration mm/s are `measurable: false` (verdict `inconclusive`, P = prior). Verdict: ≥ 0.9 `corroborated_abnormal`, ≤ 0.1 `measurement_disagreement`, else `inconclusive`. The rationale never says broken or safe. |
| `verification.ts` | `compareWithPosterior(installed, reference, baseline, opts?)` | `CompareResult` plus `pReal`, `measurable` and `posterior` (wraps `evidencePosterior`). `compareReadings` is unchanged. |
| `priors.ts` | `PRIORS: Record<FamilyId, { prior; unit; basis: 'published' \| 'model' \| 'assumption'; source; label }>`; `quantile`, `cdf`, `logpdf`, `sample` | Uniform, log-uniform, triangular, lognormal, Bernoulli (on-demand failures at the Beta posterior mean) and a lognormal mixture. Values from `docs/PREDICTION-SCIENCE.md` §3 and `research/derived/reliability_priors.json`. |
| `ensemble.ts` | `runEnsemble(input)` / `runEnsembleAsync(input)` → `Ensemble` | Two-level Monte Carlo: `outer` (default 256) parameter draws θ × `inner` (default 8) aleatory draws. Cooling-edge delays come from `zoneClocks` per θ (one draw per zone): CRAH→rack = t_off[zone], P→CRAH = t_flow − t_off, CH→P = t_chw − t_flow, so a chiller loss reaches the racks at t_chw. CDU→GPU Triangular(0.3, 0.6, 2.0) min; ATS→battery = the fixture triangle × state of health; GEN→ATS Triangular(0.15, 0.5, 3.2) min. On a utility loss: generator fail-to-start, ATS fail-to-transfer and UPS drop become faults. A fix takes effect at `t + delay · crew_mult` (chiller restart: `t + 3 · crew_mult + restart_min`); standby CRAH, chiller restart and generator can fail on demand. Water: arrival offsets from cached water-layer runs (unstopped plus 6 stop bins) scaled by `(film / 4 mm) / rate_mult` (volume-limited front, assumption). Hypotheses are Bernoulli families sampled at 0.5 with weight p/0.5. Optional defensive `mixture`: `w = p/q`, with `b/q ≤ 1/α`. Per option: weighted racks p10/p50/p90/mean; `pServiceDown` (any criticality ≥ 4 service with every replica impacted) with a CI90 from the outer-level variance (zero events: `[0, 2.3/ESS]`); minutes to the first service impact and to the 32 °C envelope; expected utility `−Σ impacted · criticality − 0.05 · crew-minutes`. `assetClocks(ens, k)` gives per-node p10/p50/p90 (needs `keepAssetTimes`). |
| `evsi.ts` | `scanEvsi(ensemble, candidates, ctx)` | `EVSI(s) = Σ_y max_a Σ_i w_i·L_y(i)·U_a(i)/Σw − max_a Σ_i w_i·U_a(i)/Σw`, from the ensemble's own trials; ties broken by `forecastShift = Σ_y p(y)·abs(P(F given y) − P(F))`. Always ≥ 0; exactly 0 when no outcome changes the best action. |
| `stress.ts` | `validateProposal`, `validateProposals`, `buildMixture`, `failureDigest`, `attributeRegions`, `crossEntropyProposals`, `stressTest` | Closed grammar (≤ 6 regions × ≤ 6 terms; quantile_window, force, set_p ≤ 0.5, scale ∈ [1/4, 4]); defensive mixture α = 0.3; per region its prior mass, P(failure given the region) and share of the failure probability. |
| `fixes.ts` | `FixContext.mode?: 'script' \| 'forecast'`, `hypotheses?`; `fixOption(action, assetId)` | `predictFix` in forecast mode uses only what is known at `ctx.t`. The run cache key covers faults, leak, hazards, steps, mode and fixes (audit C12), not just the scenario id. |
